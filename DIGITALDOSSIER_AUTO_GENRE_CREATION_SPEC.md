# DigitalDossier Auto-Genre Creation Enhancement
## Technical Specification

**Version**: 1.0  
**Date**: September 14, 2025  
**Author**: ContentRunway Development Team  
**Status**: Implementation Required

## 1. Executive Summary

This specification defines the API enhancements required for DigitalDossier blog app to support automatic genre creation when ContentRunway uploads content with new, LLM-generated genres. Instead of being limited to predefined genres, the system will intelligently create new genres as needed, enabling more precise content categorization.

## 2. Current State Analysis

### 2.1 Current API Behavior

**Endpoint**: `POST /api/upload/programmatic`  
**Current Validation**: Strict genre ID validation - rejects uploads if `genreId` doesn't exist  
**Error Response**: 
```json

  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Genre ID 104 does not exist",
```

```json
{

  "author": "Suvojit Dutta",
  "category": "Blog",
  "genreId": 104,
  "coverImage": {
    "data": "base64_encoded_image",
```

### 2.3 Current Limitations

- **Rigid Genre System**: Only accepts predefined genre IDs
- **Content Categorization Bottleneck**: Cannot create specific genres for new content types
- **LLM Intelligence Waste**: Cannot leverage AI-generated genre insights

## 3. Required Enhancement

### 3.1 Enhanced Upload Payload

The upload payload should be extended to include genre metadata that enables auto-creation:

```json
{
  "title": "The Complete Guide to Testing: Best Practices and Insights",
  "author": "Suvojit Dutta",
  "category": "Blog",
  "genreId": 578,
  "genre": {
    "id": 578,
    "name": "Software Testing",
    "description": "Content focused on software testing methodologies, best practices, and quality assurance",
    "isAutoGenerated": true,
    "confidence": 0.85,
    "domain": "Technical",
    "createdBy": "ContentRunway-LLM"
  },
  "coverImage": {
    "data": "base64_encoded_image",
    "filename": "cover.png",
    "mimeType": "image/png"
  },
  "pdfFile": {
    "data": "base64_encoded_pdf",
    "filename": "document.pdf",
    "mimeType": "application/pdf"
  }
}
```

### 3.2 Backward Compatibility

- **Existing Behavior**: If only `genreId` is provided (no `genre` object), maintain current validation
- **Enhanced Behavior**: If `genre` object is provided, use auto-creation logic
- **Fallback**: If both are provided, `genre` object takes precedence

## 4. API Endpoint Modifications

### 4.1 Enhanced Endpoint Behavior

**Endpoint**: `POST /api/upload/programmatic`  
**Enhancement**: Support auto-genre creation with extended validation logic

#### 4.1.1 Processing Logic

```pseudocode
1. Parse upload request
2. IF genre.isAutoGenerated === true:
   a. Check if genre.id already exists in database
   b. IF exists: Use existing genre
   c. IF not exists: Create new genre with provided metadata
3. ELSE:
   a. Use existing validation (genre must exist)
4. Proceed with document upload
```

#### 4.1.2 Enhanced Success Response

```json
{
  "success": true,
  "id": 25,
  "url": "http://localhost:3003/blog/25",
  "document_id": 25,
  "document_url": "http://localhost:3003/blog/25",
  "genre": {
    "id": 578,
    "name": "Software Testing",
    "wasCreated": true,
    "createdAt": "2025-09-14T12:08:43.000Z"
  }
}
```

#### 4.1.3 Enhanced Error Handling

**Case 1: Auto-creation failure**
```json
{
  "success": false,
  "error": {
    "code": "GENRE_CREATION_ERROR",
    "message": "Failed to create new genre",
    "details": {
      "field": "genre",
      "reason": "Genre name already exists with different ID"
    }
  }
}
```

**Case 2: Invalid genre metadata**
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Invalid genre metadata",
    "details": {
      "field": "genre.name",
      "reason": "Genre name must be between 1-50 characters"
    }
  }
}
```

## 6. Genre Metadata Specification

### 6.1 Genre Object Schema

```typescript
interface GenreMetadata {
  id: number;                    // Deterministic hash-based ID (100-999)
  name: string;                  // LLM-generated genre name (1-50 chars)
  description?: string;          // Optional detailed description
  isAutoGenerated: boolean;      // Always true for LLM genres
  confidence: number;            // LLM confidence score (0.0-1.0)
  domain: string;                // Content domain focus
  createdBy: string;             // "ContentRunway-LLM"
  createdAt?: string;            // ISO timestamp (server-set)
}
```

### 6.2 Content Domain Values

- `"IT Insurance"` - Insurance technology and digital transformation
- `"AI Research"` - Artificial intelligence and machine learning content  
- `"Agentic AI"` - Multi-agent systems and AI orchestration
- `"Technical"` - General technical content
- `"Business"` - Business strategy and analysis
- `"General"` - Fallback category

## 7. Implementation Requirements

### 7.1 API Validation Rules

#### 7.1.1 Genre Name Validation
- **Length**: 1-50 characters
- **Characters**: Alphanumeric, spaces, hyphens allowed
- **Uniqueness**: Case-insensitive unique check
- **Reserved Names**: Cannot use system reserved names

#### 7.1.2 Genre ID Validation  
- **Range**: 1-999 (ContentRunway uses 100-999)
- **Uniqueness**: Must be unique across all genres
- **Consistency**: Same name should always map to same ID

#### 7.1.3 Auto-Creation Limits
- **Rate Limiting**: Max 10 new genres per hour per API token
- **Admin Review**: Flag new genres for admin review
- **Audit Trail**: Log all auto-created genres with metadata

### 7.2 Database Operations

The blog app should handle these operations internally:

1. **Genre Existence Check**: `SELECT id FROM genres WHERE id = ? OR name = ?`
2. **Auto-Creation**: `INSERT INTO genres (id, name, description, created_by, created_at, is_auto_generated)`
3. **Audit Logging**: Record all auto-creation events with full metadata
